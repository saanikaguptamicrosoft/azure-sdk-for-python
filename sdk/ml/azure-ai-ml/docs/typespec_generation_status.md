# TypeSpec Generation Status

Row numbers `1-15` correspond to the table in [typespec_migration_per_version_analysis.md](typespec_migration_per_version_analysis.md) for cross-referencing.

**Scope:** TSPs are generated locally under `docs/generated-tsp/` from swaggers mirrored at `docs/swagger-remote/` (REMOTE/ARM) and `docs/swagger-local/` (LOCAL/data-plane). Nothing in `azure-rest-api-specs` is touched yet — clean TSP folders will be copy-pasted upstream once they compile with zero errors.

**Mechanical converter quirks already fixed in-place:** `@identifiers` decorator on non-array props (removed), `` `package` `` keyword escaping, missing `;` on `@@doc` augment lines and `back-compatible.tsp` `@@clientName` / `@@clientLocation` lines, `any` / `AnyObject` → `unknown`, `import` keyword escape.

**On citing Kashif's GA migration ([azure-rest-api-specs#40758](https://github.com/Azure/azure-rest-api-specs/pull/40758) + [azure-sdk-for-python#45389](https://github.com/Azure/azure-sdk-for-python/pull/45389)):** we reference his work ONLY for **mechanical / structural patterns** (e.g. converter-quirk fixes, `#suppress` discipline for legacy-API lint rules, ARM template shape options). We do NOT borrow his **wiring decisions** (`ProxyResource<X>` vs `TrackedResourceWithOptionalLocation<X>`, `@parentResource(...)`, which envelope props are re-added, which identity property is mixed in) because his TSP is hand-authored for the **GA** shape, while our affected rows are **preview / legacy** API versions whose wire contracts may intentionally differ. Any wiring-level change to a versioned `ComputeResource.tsp` (or similar) needs explicit per-version service-team confirmation that the proposed shape matches the live wire for that version.

**Other mechanical patterns from Kashif's PR available if we hit the same lint** (apply if/when triggered, not pre-emptively): `#suppress "@azure-tools/typespec-azure-core/use-standard-names"` on legacy operation names, `#suppress "@azure-tools/typespec-azure-core/casing-style"` on legacy model names (both: keep the wire stable, silence the rule), `Record<unknown>` → `Record<string>`, raw `unknown` property type → `string`, `@patch(#{implicitOptionality: true})` on PATCH ops, doc-comments on every `HttpStatusCode` union variant, and empty `examples/` folders for TSV folder-structure validation.

**Verification rule (UPDATED Jun 2026):** A row can be marked ✅ Unblocked ONLY after BOTH (a) TSP compiles 0 errors AND (b) the regenerated Python client has been imported and its `models.__all__` length diffed against the autorest client's `models.__all__`. Any Δ >5% must be investigated by grepping the SDK (`azure/ai/ml/**/*.py`) for `from azure.ai.ml._restclient.<vXXXX>.models import` and confirming every imported symbol is still in the regenerated `__all__` — a row is blocked **only if** the SDK imports at least one pruned symbol from THAT version. The same TSP defect (e.g. the `ComputeResource <{}>` converter bug) can be present in many rows' TSPs yet block only the subset whose SDK consumers touch the orphaned graph. Pre-flight: also grep the TSP folder for `// FIXME:` comments — each is a potential pruned-orphan source.
